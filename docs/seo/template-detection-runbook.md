# Template content detection + noindex runbook

Companion to `docs/seo/gsc-impressions-ctr-diagnosis-2026-11-04.md` (P0 step:
detect templated books, move them to `published_noindex`, and stop the thin
indexable surface from diluting rankings).

## Why

~1,060 of 5,027 books are indexed and most of the English catalogue was
generated by a content template. With the full-article prerender now live,
every one of those template pages publishes the full template text to Google
— so the template list must be moved off the indexable surface. Real, unique
books stay `published` and become the site's differentiating content.

## 1. Run the audit (read-only, no credentials)

From any machine with internet access and Node 20+:

```bash
git pull origin main
PRERENDER_CATALOG_API=https://www.booknomics.com node scripts/audit-template-content.mjs
```

Output (gitignored, under `out/template-audit/`):

| File | What it is |
|---|---|
| `template-audit-<date>.csv` | One row per published book: score, `recommendation` (noindex / review / keep), the signals that fired, and which signature phrases matched |
| `boilerplate-fragments.csv` | The actual shared fragments (sentences/paragraphs repeated across N books) — the template itself, for human review |
| `summary.json` | Totals, per-language counts, threshold settings, top fragments |

Signals used (deterministic, no model): shared exact sentences (≥5 books),
shared exact paragraphs (≥3 books, 120+ chars), curated template markers
(EN + HI), and byte-identical overview groups. Tunable via
`--min-sentences`, `--min-paragraphs`, `--noindex-min-score`,
`--review-min-score`.

## 2. Review (human step — do not skip)

Open the CSV sorted by `recommendation`:

1. **`noindex`** — spot-check ~20 random rows (open the book page, confirm the
   content is template). If >90% look templated, the list is safe.
2. **`review`** — read these; they sit in the middle band. Promote or demote
   by editing the `recommendation` column before applying.
3. **`keep`** — should be unique books; spot-check a few false-negative
   candidates if the `boilerplate-fragments.csv` top rows reveal new template
   phrasing (add it to `SIGNATURE_PHRASES` and re-run).

## 3. Apply (after approval)

The worker admin endpoint requires a site admin session:

1. Sign in to booknomics.com with an admin account.
2. DevTools → Application → Cookies → copy the `bn_session` value:
   `export BN_ADMIN_COOKIE="..."`
3. Dry-run (default — prints the plan, writes nothing):
   ```bash
   node scripts/apply-noindex-list.mjs --csv out/template-audit/template-audit-<date>.csv --recommendation noindex
   ```
4. Apply (rate-limited 250ms/book, retries on 429/5xx, aborts on 401/403):
   ```bash
   node scripts/apply-noindex-list.mjs --csv ... --recommendation noindex --apply
   ```
5. Restore if ever needed:
   ```bash
   node scripts/apply-noindex-list.mjs --csv ... --recommendation noindex --apply --restore
   ```

## 4. After applying

1. Trigger a Vercel production redeploy so the next prerender emits
   `noindex` robots meta on those pages (the prerender fetches only
   `status=published` for full articles; noindex books are handled by the
   en-crawl/low-volume passes with noindex meta).
2. GSC → Pages report: over the following days the noindexed URLs should move
   from "Indexed" to "Excluded / Crawled - currently not indexed".
3. Weekly: re-export Queries + Pages and compare against the baseline
   (10.1K impressions / 133 clicks / 1.3% CTR / pos 12.9 over 3 months).

## Safety notes

- The audit is strictly read-only (public catalog API, keyset pagination).
- The apply script is dry-run by default, caps per-run volume with `--limit`,
  and only ever sets `status` between `published` and `published_noindex`
  (nothing is deleted or drafted).
- `published_noindex` pages are still served and readable; they just carry a
  noindex robots meta. Reverting is one `--restore` run away.
